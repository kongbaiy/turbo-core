## 1. 设计目标与范围

### 1.1 设计目标

应用表单定义是数据域和字段的唯一事实来源。前端参照现有应用表单数据域、字段配置能力，复制通用部分并去业务化形成共享受控组件；不改动已经正常运行的平台页面，也不在合同应用内复制第二套定义模型或编辑器。

本前端负责：

1. 合同类型应用表单绑定入口、绑定状态及固定标识展示。
2. 合同类型字段配置和合同模板字段配置。
3. 数据域、字段、应用表单字段来源、合同业务来源、继承及来源模板展示。
4. 创建并关联定义、关联已有定义、修改、停用、失败详情和失败重试。
5. 显式发布、草稿 `revision` 冲突处理和整份配置刷新。
6. 合同性质在存在未删除绑定后的只读交互。
7. 合同模板专属发布 Schema 的加载入口，以及当前版本和历史版本的运行时渲染路径。

本期不负责：

1. 通用应用表单设计器的合同托管只读和删除保护。
2. 主动复用兄弟模板字段或预建模板使用关系。
3. 跨合同性质迁移。
4. 合同审批、履约、归档、变更终止等流程。
5. 由应用表单绑定或字段配置请求计算或提交 `tenantId`、`appCode`、`formCode`、菜单权限、合同性质、`definitionScope`、`sourceTemplateId`。

合同类型维护是例外：尚无未删除应用表单绑定时仍按现有接口提交 `contractType`；存在 `PENDING/ACTIVE/FAILED` 绑定后才锁定，详见第 8.4 节。

### 1.2 冻结业务参数

| 参数 | 固定值或规则 | 前端处理 |
| --- | --- | --- |
| `appCode` | `APP_CONTRACT` | 只读展示，不提交 |
| 成本合同菜单权限 | `CONTRACT_PAGE_CONTRACT_MANAGE_EXPENSE_CONTRACT` | 后端按合同性质计算，前端不提交 |
| 收入合同菜单权限 | `CONTRACT_PAGE_CONTRACT_MANAGE_BUSINESS_CONTRACT` | 后端按合同性质计算，前端不提交 |
| `formCode` | `{COST_CONTRACT\|INCOME_CONTRACT}_{合同类型编码大写}` | 后端首次绑定生成并永久保存，前端不计算、不修改 |
| `definitionScope` | `TENANT` | 后端固定，前端不提交 |
| 默认存储模式 | `UNIFIED_DATA` | 普通用户不提供 `PHYSICAL_TABLE` 选项 |
| 类型与表单 | 一个具体合同类型一张独立表单 | 不提供任意选表、换表或换码入口 |

## 2. 当前前端现状

本章结论来自当前工作树，不依据旧文档推测。

### 2.1 合同类型页面

`apps/sc-cloud-contract/src/pages/contract-manage/contract-category/index.tsx` 当前结构如下：

1. 顶部 `Tabs` 切换 `COST_CONTRACT`、`INCOME_CONTRACT`。
2. 左侧使用 Ant Design `Tree` 管理合同类型树，支持新增一级、新增子级、查看、编辑和删除。
3. `dataType='0'` 为分组，`dataType='1'` 为具体合同类型；只有具体类型进入右侧配置区。
4. 右侧已有“数据域及字段配置待后续功能实现”占位，是类型字段配置的直接接入点。
5. 类型表单位于 `components/contract-category-drawer.tsx`，使用 `DrawerForm`、`ProFormTreeSelect` 等；当前编辑态仍允许修改 `contractType`，必须增加绑定锁定逻辑。
6. 现有样式已经使用左右分栏、`min-height: 0` 和独立滚动边界，应沿用而不是重做页面。

`src/api/contract-category` 目前只有树、详情、新增、修改和删除接口，响应模型尚无应用表单绑定摘要或合同性质锁定信息。

### 2.2 合同模板页面

`apps/sc-cloud-contract/src/pages/contract-manage/contract-template/index.tsx` 当前结构如下：

1. 使用 `ProTable`，支持关键字、合同分类、合同性质和模板状态筛选。
2. 分页使用 `usePaginationConfig()`，页面把响应适配成 `{ data, total, success }`。
3. 支持新增、查看、编辑、状态修改和删除；编辑使用 `ContractTemplateDrawer`。
4. 字典通过 `useDictOptions` 获取，展示优先 `xxxDesc || xxx`。
5. 展开行已有“模板字段配置待后续功能实现”占位，可改成字段摘要和“配置字段”入口。

`src/api/contract-template` 目前只有分页、详情、保存、修改、删除和状态修改接口。

### 2.3 API、路由和菜单

1. API 使用 `@repo/utils` 的 `api`，并由 `apps/sc-cloud-contract/src/api/index.ts` 统一导出；现有 URL 含网关前缀 `/api`。
2. `src/router/contract-menu.ts` 定义本地菜单，合同类型和模板组件键分别为 `contract-category`、`contract-template`。
3. `src/router/index.tsx` 通过 `componentMap` 装配页面；未映射叶子项落到 `PlaceholderPage`。
4. Qiankun 下 `basename='/contract'`，独立运行时为 `/`。
5. 费用合同、经营合同当前仍是占位叶子菜单，没有运行时页面组件。

### 2.4 现有应用表单配置能力

`apps/sc-cloud-platform/src/pages/business-standard/form-manage/app-form-data-domain-config.tsx` 已实现数据域树、字段属性、平台字段池、自定义字段、规则、草稿、校验、发布和 409 提示，但不能整页跨应用引用：

1. 文件位于平台应用内部，直接 import 平台私有 API 和类型。
2. 组件内部持有版本、草稿、字段池、规则、预览、发布等平台专属状态。
3. 平台通过 `saveFormDataDomainConfiguration` 保存整份域和字段快照；合同接口是逐项创建、关联、修改、停用和重试。
4. 当前文件约 1783 行，直接增加合同分支会放大耦合，也违反页面拆分要求。
5. 平台字段使用 `fieldScope='PLATFORM_STANDARD'`、`metadataFieldId/metadataFieldCode`；自定义字段使用 `fieldScope='TENANT_CUSTOM'`。现有页面显示时已归一成 `SYSTEM/CUSTOM`，这一语义可提取。
6. 当前平台配置允许 `PHYSICAL_TABLE`，合同普通用户只允许 `UNIFIED_DATA`，需要由能力参数约束。

因此采用“保留平台现状 + 复制通用能力形成共享受控组件 + 合同适配层”。不移动、不重构、不回接现有 `AppFormDataDomainConfig`，也不给它增加合同分支或接口 URL 参数。复制后必须删除平台 API、版本、草稿、规则、预览和发布等耦合，只保留可复用 UI、校验及纯转换逻辑。

这是本期确认的隔离策略：共享组件仅服务新增合同能力，不要求平台页面回接；平台现有功能的代码、调用链和行为均不受影响。

## 3. 页面信息架构

### 3.1 页面组织结论

采用现有页面内嵌入口，不新增配置路由：

- 合同类型：保留左树右内容结构，右侧直接呈现类型配置。
- 合同模板：展开行呈现摘要和入口，点击后打开宽 Drawer。
- 共享定义配置组件：嵌入类型右侧或模板 Drawer，不拥有路由和业务弹层。
- 关联已有、失败详情、发布确认：合同专属 Modal。
- 数据域、字段新增编辑：共享组件内部的通用 Drawer/Form，由适配层回调执行操作。

这样与现有合同类型、模板交互一致，也避免在 ProTable 展开行中塞入完整编辑器。

### 3.2 合同类型页面

右侧自上而下分为：

1. **应用表单绑定状态区**：绑定状态、表单名称、`appCode`、`formCode`、菜单权限、草稿版本、当前发布版本、`revision`。
2. **数量摘要**：数据域数、字段数、类型定义项数、模板定义项数、未关联项数、失败项数。
3. **操作区**：无绑定时显示“绑定应用表单”；已绑定时显示“刷新”“配置字段”“失败重试”“发布”。按钮以服务端能力为准。
4. **定义配置区**：共享组件展示域和字段；合同外壳增加“合同类型定义/模板定义”、来源模板、关系状态、失败摘要列。
5. **类型视图规则**：类型定义可维护；模板定义可见并显示来源模板，但不能从类型上下文冒充模板修改；未关联候选通过合同 Modal 处理。

配置查询必须是纯读。无绑定时只能由用户点击绑定动作触发后端定位或创建，不在 GET 中偷偷写入。

### 3.3 合同模板页面

ProTable 展开行只显示：类型继承数、本模板定义数、失败数、当前发布版本和“配置字段”按钮。宽 Drawer 内包含：

1. 类型继承项：`CONTRACT_TYPE`，标记“类型继承”，只读。
2. 当前模板定义项：`CONTRACT_TEMPLATE` 且来源模板为当前模板，可维护。
3. 在已有有效数据域新增字段。
4. 新增数据域及字段。
5. 关联后端返回的未关联定义候选。
6. 当前模板关系的失败详情和重试。

兄弟模板定义项由后端配置聚合接口排除，前端不展示、不自行过滤，也不提供主动复用入口。

### 3.4 展示列

字段 `ProTable` 至少包含：字段名称、`fieldCode`、值类型、控件类型、应用表单字段来源、合同业务来源、来源模板、继承标识、必填、只读、可见、排序、关系状态、失败摘要和操作。

数据域标题至少包含：域名称、`domainCode`、OBJECT/LIST、存储模式、字段数量、合同业务来源、来源模板、关系状态。`domainKey/fieldKey` 为关联和请求标识，不作为主视觉信息；详情中可复制查看。

## 4. 前端组件设计

### 4.1 分层与组件树

```text
apps/sc-cloud-platform/.../form-manage/
└── AppFormDataDomainConfig（现有实现保持不变，仅作为复制来源）

packages/react-components/app-form-definition-config/
└── AppFormDefinitionConfig（复制并去业务化后的受控组件）
    ├── DefinitionDomainList
    ├── DefinitionFieldTable
    ├── DefinitionDomainDrawer
    ├── DefinitionFieldDrawer
    └── RevisionConflictModal

apps/sc-cloud-contract/.../field-configuration/
└── ContractDefinitionConfiguration（合同适配层/页面状态）
    ├── ContractBindingSummary
    ├── ContractDefinitionSourceColumns
    ├── AppFormDefinitionConfig
    ├── AssociateDefinitionModal
    ├── FailureDetailModal
    └── PublishConfirmModal
```

合同应用不再建设自己的 `DataDomainDrawer`、`FieldDefinitionDrawer` 或第二套数据域/字段表单。

### 4.2 共享受控模型

共享组件只表达应用表单定义协议，不表达合同绑定、来源模板、关系状态或平台表单版本。建议最小类型如下；最终属性名以抽取时的现有平台类型和 OpenAPI 对齐：

```typescript
interface AppFormDefinitionConfigurationValue {
    revision?: number
    domains: AppFormDefinitionDomain[]
}

interface AppFormDefinitionDomain {
    id?: string
    domainKey?: string
    domainCode: string
    domainName: string
    domainType: 'OBJECT' | 'LIST'
    storageMode: 'UNIFIED_DATA' | 'PHYSICAL_TABLE'
    sortNo?: number
    status?: string
    readonly?: boolean
    fields: AppFormDefinitionField[]
}

interface AppFormDefinitionField {
    id?: string
    fieldKey?: string
    fieldCode: string
    fieldName?: string
    fieldLabel?: string
    uiLabel?: string
    valueType?: string
    controlType?: string
    metadataFieldId?: string
    metadataFieldCode?: string
    appFieldSource: 'SYSTEM' | 'CUSTOM'
    required?: boolean
    readonly?: boolean
    visible?: boolean
    sortNo?: number
    status?: string
    editable?: boolean
}
```

共享类型不是第二套服务端事实模型：它只是受控 UI 的展示和编辑模型。合同适配层从 `ContractDefinitionConfigurationRVO` 映射，并在提交时转回合同 OpenAPI 类型。现有平台页面继续直接使用自己的 `AppFormDesigner`，不接入该共享类型。

### 4.3 共享组件 Props 与职责

```typescript
interface AppFormDefinitionConfigProps {
    value: AppFormDefinitionConfigurationValue
    capabilities: AppFormDefinitionCapabilities
    options: AppFormDefinitionOptions
    loading?: boolean
    submitting?: boolean
    conflict?: boolean
    renderDomainMeta?: (domain: AppFormDefinitionDomain) => React.ReactNode
    extraFieldColumns?: ProColumns<AppFormDefinitionField>[]
    onSelectDomain?: (domainKey: string) => void
    onCreateDomain: (input: AppFormDomainInput) => Promise<void>
    onCreateField: (domainKey: string, input: AppFormFieldInput) => Promise<void>
    onUpdateDefinition: (
        target: AppFormDefinitionTarget,
        input: AppFormDomainInput | AppFormFieldInput,
    ) => Promise<void>
    onDisableDefinition: (target: AppFormDefinitionTarget) => Promise<void>
    onPublish?: () => Promise<void>
    onReload: () => Promise<void>
}
```

`renderDomainMeta` 用于在域标题注入合同来源、来源模板和关系状态；`extraFieldColumns` 用于注入字段来源、来源模板、继承、关系状态和失败摘要列。两个回调由合同适配层闭包读取 `contractMetaByKey`，不把合同元数据写入共享 `value`。本期只保留这两个固定扩展点，不设计插件系统。

职责边界：

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| `AppFormDefinitionConfig` | 域选择、字段表、空态、通用操作编排 | 请求、版本定位、合同来源关系 |
| `DefinitionDomainList` | 域名称、类型、存储、数量、选择 | 页面级请求状态 |
| `DefinitionFieldTable` | 通用字段列、只读/禁用能力、排序展示 | 合同来源列的业务判定 |
| `DefinitionDomainDrawer` | 通用域表单和校验 | 绑定、relation、平台发布 |
| `DefinitionFieldDrawer` | 通用字段表单、SYSTEM/CUSTOM 边界、选项联动 | 自行查询字段池、字典或控件接口 |
| `RevisionConflictModal` | 标准冲突提示并触发 `onReload` | 识别 Axios 错误或自动合并 |

`options` 由合同适配层提供值类型、控件、数据源、安全级别和字段池候选；共享组件不 import `@/api`。`capabilities` 只包含当前配置场景真实需要的开关，例如创建、修改、停用、发布、允许的存储模式和字段级只读能力，不设计插件系统、工厂或动态注册框架。

### 4.4 状态归属

页面/适配层持有：配置聚合结果、绑定、版本、`revision`、权限能力、请求 loading、冲突状态、合同关系弹窗状态。共享子组件只持有 Drawer 开关、表单输入和当前选中域等短生命周期 UI 状态；关闭后清理。

现有平台组件继续独立持有版本列表、草稿创建、字段池、规则、预览、整份保存、校验和发布，代码和调用链均不调整。合同适配层持有绑定、来源、继承、relation、失败重试和逐项写操作，并通过 Props 驱动共享组件。

任何页面 `index.tsx` 不超过 600 行；按上述业务职责拆分，不建立只有一次转发的工厂或无业务意义的通用组件。

## 5. API 与 TypeScript 类型设计

### 5.1 API 目录

合同新增：

```text
apps/sc-cloud-contract/src/api/contract-definition/index.ts
apps/sc-cloud-contract/src/api/contract-definition/index.interface.ts
apps/sc-cloud-contract/src/api/contract-definition/adapter.ts
apps/sc-cloud-contract/src/api/contract-runtime/index.ts
apps/sc-cloud-contract/src/api/contract-runtime/index.interface.ts
```

`contract-definition` 承载第一阶段绑定和配置；`contract-runtime` 承载第二阶段 Schema、合同记录和选项代理。两者只调用 `/api/admin/enterprise/contract/...`，不得调用 `/internal/...` 或企业基础应用表单管理 URL。

### 5.2 后端详细设计已明确的 REST

前端方法名建议如下，路径以文档中的业务路径加现有网关前缀 `/api`：

| 方法 | REST | 用途 |
| --- | --- | --- |
| `bindContractTypeAppForm` | `PUT /api/admin/enterprise/contract/types/{contractTypeId}/app-form-binding` | 无请求体，定位或创建绑定 |
| `getContractTypeFieldConfiguration` | `GET /api/admin/enterprise/contract/types/{contractTypeId}/field-configuration` | 类型草稿聚合配置 |
| `createOrAssociateTypeDomain` | `POST /api/admin/enterprise/contract/types/{contractTypeId}/data-domains` | 创建或关联类型域 |
| `createOrAssociateTypeField` | `POST /api/admin/enterprise/contract/types/{contractTypeId}/data-domains/{domainKey}/fields` | 创建或关联类型字段 |
| `getContractTemplateFieldConfiguration` | `GET /api/admin/enterprise/contract/templates/{templateId}/field-configuration` | 模板有效配置 |
| `createOrAssociateTemplateDomain` | `POST /api/admin/enterprise/contract/templates/{templateId}/data-domains` | 创建或关联模板域 |
| `createOrAssociateTemplateField` | `POST /api/admin/enterprise/contract/templates/{templateId}/data-domains/{domainKey}/fields` | 创建或关联模板字段 |
| `updateContractDefinitionRelation` | `PUT /api/admin/enterprise/contract/definition-relations/{relationId}` | 修改合法来源定义 |
| `disableContractDefinitionRelation` | `DELETE /api/admin/enterprise/contract/definition-relations/{relationId}` | 停用关系及草稿定义 |
| `retryContractDefinitionRelation` | `POST /api/admin/enterprise/contract/definition-relations/{relationId}/retry` | 重试失败关系 |
| `publishContractTypeAppForm` | `POST /api/admin/enterprise/contract/types/{contractTypeId}/app-form/publish` | 显式发布整张类型表单 |
| `getContractTemplateRenderSchema` | `GET /api/admin/enterprise/contract/templates/{templateId}/render-schema` | 当前模板专属发布 Schema |

所有 path 参数使用 `encodeURIComponent`，尤其是 `domainKey`。若后端最终把字段创建的域定位改为 `domainRelationId`，前端跟随 OpenAPI，不能退回版本内 `dataDomainId`。

### 5.3 配置聚合 RVO 映射

后端详细设计已冻结的是结构语义，不是全部 JSON 字段。前端接口类型先按 OpenAPI 生成/核对后再落地，不能把本文示意当作已存在字段：

```typescript
interface ContractDefinitionConfigurationRVO {
    binding?: ContractAppFormBindingRVO
    draft?: ContractDraftRVO
    published?: ContractPublishedVersionRVO
    dataDomains: ContractDefinitionDomainRVO[]
}

interface ContractDefinitionDomainRVO {
    appFormDefinition: AppFormDomainDefinitionRVO
    relation?: ContractDefinitionRelationRVO
    fields: ContractDefinitionFieldRVO[]
}

interface ContractDefinitionFieldRVO {
    appFormDefinition: AppFormFieldDefinitionRVO
    relation?: ContractDefinitionRelationRVO
    inheritedFlag?: boolean
}
```

已明确的 binding 语义包括 `appCode/formCode/formName/menuPermissionCode/menuId/status`；draft 包含 `versionId/versionNo/revision`；published 包含 `versionId/versionNo`；relation 包含 `relationId/source/sourceTemplate/status`。`sourceTemplate` 的实际对象结构、错误摘要、计数和能力字段必须以 OpenAPI 为准。

adapter 输出两部分：

1. `sharedValue`：只含共享组件所需的域、字段和应用表单定义属性。
2. `contractMetaByKey`：以 `domainKey/fieldKey` 索引合同来源、模板、继承、relation 状态、失败和操作能力。

ProTable 行键优先 `fieldKey`；尚未取得稳定键的失败关系使用后端返回的 `relationId`，不使用数组下标。域选择键优先 `domainKey`。

### 5.4 请求类型边界

后端详细设计仅明确 `ContractDefinitionAssociationQVO` 的语义：

```text
associationMode: ASSOCIATE_EXISTING / CREATE_AND_ASSOCIATE
expectedRevision
domainKey / fieldKey：关联已有时使用
domainCode / fieldCode：创建时使用
dataDomainDefinition：创建数据域时使用强类型对象
fieldDefinition：创建字段时使用强类型对象
```

最终 TypeScript 请求类型必须逐字段映射 OpenAPI；在 OpenAPI 未冻结前，不在前端先造 `dataDomainDefinition`、`fieldDefinition` 的字段全集。必须遵守：

- 绑定请求没有 body。
- 类型/模板来源由 URL 上下文决定，不提交 `definitionSource` 或 `sourceTemplateId`。
- 任何请求不含 `tenantId/appCode/formCode/menuPermissionCode/contractType/definitionScope`。
- 创建、关联、修改、停用和发布按最终契约携带 `expectedRevision`。
- `xxxDesc` 仅属于响应展示，不进入请求。

### 5.5 稳定键、字典和 ProTable 适配

- `domainKey/fieldKey`：跨草稿和发布版本的长期关联键，用于选择、更新、关联和运行时有效集；`dataDomainId/fieldId` 仅是版本快照。
- `revision`：加载草稿时保存，所有定义写操作使用 `expectedRevision`。
- 带 OpenAPI `x-dict-code` 的响应字段增加 `xxxDesc?`，展示用 `xxxDesc || xxx`；输入选项通过 `useDictOptions` 或合同业务接口返回选项获取。
- 配置聚合不是分页接口，适配成共享组件数组；模板列表继续适配 `{ data: records, total, success: true }`。
- 合同关系列由 `contractMetaByKey` 补充，不能污染共享应用表单定义类型。

### 5.6 实施前需后端冻结或补充

以下能力未在当前后端详细设计中形成完整 OpenAPI，前端不得假定已存在：

1. `ContractDefinitionConfigurationRVO` 全量字段、字典标注、来源模板结构、统计信息和失败摘要。
2. 配置级及行级 `canBind/canCreate/canUpdate/canDisable/canRetry/canPublish` 等权限能力，或等价权限契约。
3. `dataDomainDefinition/fieldDefinition` 的强类型创建、更新字段；每个写接口的响应及新 `revision`。
4. SYSTEM/CUSTOM 的响应字段名、SYSTEM 字段池候选和合同业务代理接口。
5. 值类型、控件类型、数据源、安全属性的选项来源及字典编码。
6. 未关联定义候选的获取方式、已被其他模板占用的不可选原因和版本一致性信息。
7. 关系失败的脱敏摘要、失败时间、可重试标识和详情。
8. 合同类型详情或绑定摘要中用于锁定 `contractType` 的稳定字段；非法修改的 409 错误码。
9. 当前 Schema 的 `namePath/htmlName`、`domainKey/fieldKey` 最终形状。
10. 第 10.4 节列出的按 `formVersionId/formVersionNo` 读取应用表单版本的历史 Schema、合同记录和选项代理接口闭环。

## 6. 状态管理与请求流程

### 6.1 首次进入类型配置

1. 加载类型树并选中具体类型。
2. 请求类型配置聚合接口；GET 只读，不自动建表单、草稿或关系。
3. adapter 原子映射 `sharedValue + contractMeta + revision + capabilities`。
4. 有绑定和草稿时渲染配置；无绑定显示绑定空态；无草稿显示明确异常，不拿发布版冒充草稿。
5. 切换类型时用请求序号或 `AbortController` 阻止旧响应覆盖新页面，不引入全局状态库。

### 6.2 绑定应用表单

1. 显示固定规则和“绑定应用表单”。
2. 点击后调用无 body 的绑定接口。
3. 后端读取类型和合同性质，定位或创建 `APP_CONTRACT + TENANT + formCode`。
4. 成功后整份刷新；`PENDING/FAILED` 展示后端摘要和可用重试能力。

### 6.3 创建数据域和字段

1. 共享 Drawer 使用适配层提供的选项和能力。
2. 合同新域默认、且普通用户仅能选择 `UNIFIED_DATA`；类型为 `OBJECT/LIST`。
3. CUSTOM 字段在共享表单校验后，由合同适配层组装 OpenAPI 的 `CREATE_AND_ASSOCIATE` 请求。
4. SYSTEM 字段由字段池候选选择，不允许自由填写平台字段编码。
5. 写成功先采用响应的新 revision，再整份刷新获得后端最终 `domainKey/fieldKey` 和关系状态；若响应没有 revision，刷新完成前禁止继续写。

### 6.4 关联已有定义

1. 合同 `AssociateDefinitionModal` 只展示后端认定的未关联候选。
2. 选择字段时校验其归属域；请求使用 `ASSOCIATE_EXISTING`、稳定键和 `expectedRevision`。
3. 类型入口的来源由 type URL 决定；模板入口的来源由 template URL 决定。
4. 成功后刷新整份配置，不在前端复制定义快照。

### 6.5 修改、停用和失败重试

- 修改只对后端允许且属于当前维护上下文的定义开放；稳定编码只读。
- 停用弹出确认，调用 relation 接口；级联影响由后端校验并返回。
- 只有 `FAILED` 且后端允许重试的关系显示“重试”。重试成功后刷新，不重新要求用户填写原命令。
- `PENDING` 禁止重复点击；`DISABLED` 默认不参与有效配置，可在“已停用”筛选查看。

### 6.6 显式发布

1. 存在本地未提交表单、`PENDING/FAILED` 或后端 `canPublish=false` 时禁用发布。
2. 确认 Modal 展示表单、草稿版本、当前发布版本、revision 和“发布会影响该合同类型全部模板的新建合同”。
3. 发布按 OpenAPI 携带 `expectedRevision`；成功后刷新配置，失败不改变当前发布版本展示。

### 6.7 页面关闭和重新进入

模板 Drawer 关闭时丢弃配置、revision、冲突和子弹层状态；重开必须重新加载。类型切换也重新加载，不缓存可能过期的草稿。模板操作成功只刷新当前 ProTable 页，不改变筛选和页码。

## 7. revision 并发处理

1. 配置加载时保存后端草稿 `revision`。
2. 每次定义创建、关联、修改、停用和发布携带 `expectedRevision`。
3. 写成功使用后端返回的新 revision；不能由前端 `+1` 推算。
4. 收到 HTTP 409 后立即停止链式提交，关闭 submitting，并将页面切为不可继续写的冲突态。
5. 共享冲突 Modal 显示“表单定义已变化，请刷新后重试”。
6. 用户确认后由适配层重新加载整份配置；取消时保留当前内容供查看，但写操作保持禁用。
7. 不自动合并、不自动覆盖其他用户修改，也不把旧 Drawer 值重放到新 revision。

合同适配层负责识别合同请求的 409，并驱动共享冲突 UI。平台页面继续使用现有 409 处理，不因本功能改变。

## 8. 来源、继承和权限交互

### 8.1 两个来源维度

| 维度 | 值 | 含义 |
| --- | --- | --- |
| 应用表单字段来源 | `SYSTEM/CUSTOM` | 字段元数据来自平台字段池或租户自定义 |
| 合同业务来源 | `CONTRACT_TYPE/CONTRACT_TEMPLATE` | 定义由合同类型或哪个模板引入 |

两者必须使用不同属性、不同列和不同 Tag。不能用一个 `source` 同时承载两种语义。

### 8.2 继承和隔离

| 页面与来源 | 展示 | 编辑 |
| --- | --- | --- |
| 类型页 `CONTRACT_TYPE` | 合同类型定义 | 可维护 |
| 类型页 `CONTRACT_TEMPLATE` | 模板定义 + 来源模板名 | 仅查看来源；从对应模板入口维护 |
| 模板页类型来源 | 类型继承 | 全部只读 |
| 模板页当前模板来源 | 本模板定义 | 可维护 |
| 模板页兄弟模板来源 | 后端不返回，前端不展示 | 无入口 |

模板继承项的 `readonly` 由合同 adapter 计算为展示能力，但后端仍负责最终校验。前端不能通过“不过滤请求字段”来复用兄弟模板定义。

### 8.3 关系状态和权限

- `PENDING`：处理中，禁用重复动作。
- `ACTIVE`：有效；在来源和权限允许时可维护。
- `FAILED`：展示失败摘要、详情和后端允许时的重试。
- `DISABLED`：已停用，不参与有效 Schema。

状态展示优先 `statusDesc || status`。按钮同时依据页面权限和后端能力；前端隐藏/禁用只是交互控制，服务端必须再次鉴权并校验模板有效字段。403 使用 `Result status='403'`。

### 8.4 合同性质锁定

当前 `contract-category-drawer.tsx` 编辑态允许修改 `contractType`，后续必须改为：

1. 无任何未删除应用表单绑定时，`contractType` 按现有业务规则可编辑。
2. 存在 `PENDING/ACTIVE/FAILED` 任一未删除绑定时，编辑态的 `contractType` 只读，并在控件下显示“已绑定应用表单，合同性质不可修改”。
3. 锁定依据必须来自后端类型详情/绑定摘要，不能仅根据当前页面是否加载过配置猜测。
4. 前端更新请求保持现有请求结构，但锁定时不允许用户改变值；后端对绕过前端的非法修改返回 409。
5. 收到该 409 时保留 Drawer，刷新详情并显示锁定原因，不覆盖后端值。

## 9. 应用表单字段编辑协议

### 9.1 数据域

共享域 Drawer 覆盖名称、编码、类型、存储模式、排序和状态。`domainKey` 是稳定关系键，`domainCode` 是运行时 payload key；创建后均不可随意改变。类型只用真实协议 `OBJECT/LIST`。

合同场景默认 `UNIFIED_DATA`，普通用户不显示 `PHYSICAL_TABLE` 选项。共享组件保留通用的 `allowedStorageModes` 能力，但本期合同适配层只传入 `UNIFIED_DATA`；现有平台页面的 `PHYSICAL_TABLE` 行为保持原样。

### 9.2 CUSTOM 字段

共享字段 Drawer 覆盖字段名称、字段编码、值类型、控件类型、必填、只读、可见、排序、状态、数据源和安全属性。创建 CUSTOM 字段的最终请求参数来自 OpenAPI；至少需要能表达上述业务属性及所属域，不能用 `Map<string, unknown>` 代替强类型协议。

`fieldCode` 是应用表单稳定运行时编码，创建后只读。值类型、控件、数据源和安全属性选项由适配层提供；有 `x-dict-code` 的字段使用 `useDictOptions`，数据源使用对应业务接口候选。

### 9.3 SYSTEM 字段

SYSTEM 字段从平台字段池候选选择：

1. 合同场景的候选必须由合同业务代理接口提供，共享组件不发请求；现有平台页面仍直接使用自己的字段池接口。
2. 保存关联的 `metadataFieldId/metadataFieldCode`，实际字段名以 OpenAPI 为准。
3. 平台字段编码不能由用户自由输入；`fieldCode` 由平台字段身份和后端规则产生或返回。
4. SYSTEM 的元数据名称、值类型、安全属性等按后端能力只读；允许覆盖的 UI 标签、控件或展示属性只在 OpenAPI 明确后开放。

复制通用逻辑时可参考平台内部值 `PLATFORM_STANDARD/TENANT_CUSTOM` 到 `SYSTEM/CUSTOM` 的现有展示语义，但不新增或修改平台适配层，也不改原工具函数。合同接口应明确自己的响应字段，不要求合同应用理解平台私有 `fieldScope`。

### 9.4 只读边界

- SYSTEM 元数据：默认只读，按服务端允许覆盖字段例外开放。
- CUSTOM：仅创建来源且当前上下文有权限时可维护。
- 类型继承项：模板页面全部只读，不论其应用表单来源是 SYSTEM 还是 CUSTOM。
- 当前模板项：按来源关系和权限维护。
- 兄弟模板项：不返回、不展示。

共享组件只执行传入的 `editable/readonly/capabilities`；合同 adapter 负责合同来源判定，服务端作最终校验。

## 10. 模板运行时 Schema

### 10.1 复用边界

复用 `packages/react-components/app-form-runtime` 的 Schema、控件注册器和编辑/详情/List 渲染器。默认 `general-template-1/runtime-client.ts` 会调用企业基础应用表单 URL，合同页面不能直接使用；需实现合同 runtime client，并继续复用 `runtime-data-adapter.ts` 的版本与 `dataDomains` 转换思路。

### 10.2 新建合同

1. 成本/收入合同页面先取得用户选择的 `templateId`；templateId 来源接口需后端冻结。
2. 调用合同模板业务接口加载该模板当前已发布、模板专属 Schema。
3. 前端不读取草稿，不自行过滤兄弟模板字段。
4. 按 `pageLayout.designTree` 渲染；OBJECT 域使用对象，LIST 域使用数组。
5. 保存时将 `schema.form.versionId/versionNo` 映射为请求的 `formVersionId/formVersionNo`，字段值按 camelCase `domainCode/fieldCode` 放入 `dataDomains`。

### 10.3 编辑或查看历史合同

1. 先加载合同记录控制信息，取得创建时固定的 `formVersionId/formVersionNo` 和 `templateId`。
2. 再以“模板上下文 + 固定表单版本”请求模板专属历史 Schema；该应用表单版本本身包含当时的数据域和字段定义。
3. 使用该版本 Schema 解释和编辑历史 `dataDomains`；不得回退当前草稿、当前发布版本，也不由前端按当前配置推导历史字段。
4. 保存继续携带记录固定版本，并按 `recordVersion/expectedVersion` 做记录乐观锁。

本设计不新增合同侧数据域/字段定义历史快照。后端按固定 `formVersionId/formVersionNo` 读取对应应用表单版本，再结合 `templateId` 返回模板专属 Schema。当前后端详细设计没有冻结该路径，实施前必须补齐；本文不虚构 URL 或 method。

### 10.4 第二阶段运行时接口闭环

除已设计的“当前模板发布 Schema”外，以下均需在实施前通过后端详细设计和 OpenAPI 冻结：

| 能力 | 最小契约要求 | 当前状态 |
| --- | --- | --- |
| 成本/收入合同模板候选 | 页面上下文能取得合法 `templateId` | 待冻结 |
| 当前模板 Schema | 模板上下文、已发布版本、`formVersionId/formVersionNo` | 路径已有设计，响应待 OpenAPI |
| 历史模板 Schema | 接收模板上下文和固定 `formVersionId/formVersionNo`，读取该应用表单版本的数据域和字段 | 待冻结，不假定路径 |
| 合同记录分页 | 模板条件、分页、查询条件、返回固定版本 | 待冻结 |
| 合同记录详情 | `templateId`、`formVersionId/formVersionNo`、`dataDomains`、记录版本 | 待冻结 |
| 合同记录新增/编辑 | `dataDomains`、表单版本、`recordVersion/expectedVersion` | 待冻结 |
| 合同记录删除 | 是否允许、权限、乐观锁和引用限制 | 待产品/后端确认 |
| 字典/引用选项代理 | template + form version + domainCode + fieldCode，分页/关键字 | 待冻结 |
| 服务端字段校验 | 只接受该模板在指定应用表单版本内的有效稳定键集合 | 待冻结 |

合同 API 必须位于 `/api/admin/enterprise/contract/...`。即便 Schema 带 `apiBindings`，合同 runtime client 也要限制为同源合同业务路径，不能退回企业基础接口。

### 10.5 渲染和提交协议

Schema 的 `namePath` 存在时优先作为 Ant Design Form 路径，`htmlName` 仅用于需要原生 name 的控件；无值时保持当前 `[domainCode, fieldCode]` 推导。当前共享 `AppFormRuntimeField` 尚未声明二者，需在后端协议冻结后最小补充可选类型和渲染优先级。

提交形状：

版本字段固定映射：`schema.form.versionId -> formVersionId`、`schema.form.versionNo -> formVersionNo`。前端不得从当前发布版本覆盖历史合同记录中的固定版本。

```typescript
{
    recordId,
    expectedVersion,
    recordVersion,
    formVersionId,
    formVersionNo,
    dataDomains: {
        [domainCode]: { [fieldCode]: value },
        [listDomainCode]: [{ [fieldCode]: value }],
    },
}
```

实际控制字段以 OpenAPI 为准；不提交 `tenantId`。字典和引用选项优先使用 Schema 内联选项，否则调用合同代理。前端不自行过滤兄弟模板字段，后端必须按模板、稳定键和指定应用表单版本再次校验。

## 11. 加载、空态、异常和反馈

| 场景 | 处理 |
| --- | --- |
| 页面加载中 | 主内容 `Spin`，保留类型/模板上下文 |
| 无表单绑定 | `Empty` + 有权限时“绑定应用表单” |
| 无数据域 | `Empty` + 新增域/关联已有入口 |
| 数据域无字段 | 字段区 `Empty` + 新增字段入口 |
| 草稿不存在 | `Result` 或 `Alert` 明示，不自动创建草稿 |
| 关联失败 | 状态 Tag + 脱敏摘要 + 失败详情 Modal |
| revision 冲突 | `Modal.confirm` 提示刷新整份配置 |
| 发布失败 | 保留当前发布版本，短提示用 `message`，详情用 `Alert/Modal` |
| 定义不存在/版本不一致 | `Alert type='warning'`，禁用写操作并提供刷新 |
| 网络失败 | 保留上下文并提供重试；拦截器已提示时不重复 message |
| 无权限 | `Result status='403'`，不当作网络错误 |
| 历史 Schema 不存在 | `Result` 明示固定版本不可用，禁止用当前版本兜底 |

`message` 只用于成功和短反馈；需用户决策的停用、发布、冲突使用 Modal；持续异常使用 Alert/Result。组件能力采用 Ant Design 6 现有 `open`、`loading`、`destroyOnHidden` 等模式，不覆盖内部 DOM 模拟功能。
