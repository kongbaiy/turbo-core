# 设计规范_布局 Layout0.5_可执行规范

> 本文档用于研发、设计、AI 辅助开发时执行布局规范。来源为 `设计规范_布局 Layout0.5.pdf` 与对应还原文档 `设计规范_布局 Layout0.5.md`。  
> 本文只做规则梳理，不替代原始规范。遇到数值或视觉细节争议时，以原始 PDF 为准。

## 1. 适用范围

本规范适用于后台管理类页面、业务系统页面、列表页、表单页、弹窗、抽屉、表格、搜索栏、页签、标签、导航等界面。

页面实现时必须优先保证：

1. 页面结构清晰。
2. 左右布局稳定。
3. 内容区滚动边界明确。
4. 字体、颜色、间距、圆角、阴影使用统一参数。
5. 表单、表格、搜索、导航等通用页面模式一致。

## 2. 规范等级

| 标识 | 执行含义 |
| --- | --- |
| 必须 | 默认强制执行，除非业务场景明确不适用 |
| 建议 | 最佳实践，优先执行；如不执行，需要有明确原因 |
| 过渡期 | 规范过渡期间可暂时存在，但新页面不应主动采用 |

## 3. 页面主体布局

### 3.1 基础结构

必须采用页面级左右布局：

```text
Header
Sidebar + Content
```

执行要求：

1. 页面顶部为全局顶部栏。
2. 左侧为导航菜单，可展开、可收起。
3. 右侧为业务内容区。
4. 内容区内部根据页面类型组织搜索区、操作区、页签、表格、表单等模块。

### 3.2 左侧菜单宽度

| 状态 | 宽度 |
| --- | --- |
| 展开 | 200px |
| 收起 | 100px |

执行要求：

1. 展开态展示完整菜单文字。
2. 收起态只保留必要识别信息。
3. 左侧导航宽度固定，右侧内容区自适应。

### 3.3 顶部栏高度

顶部栏高度按 `40px` 执行。

顶部栏内容包括：

1. 主菜单入口。
2. 产品名称或服务页签。
3. 全局功能区。
4. 账号信息。

### 3.4 页面内容滚动

必须明确滚动边界：

1. 页面外层不应产生无意义横向滚动。
2. 左侧菜单内容超过高度时，左侧菜单内部纵向滚动。
3. 右侧内容超过高度时，应由业务内容区内部滚动。
4. 表格页面应优先让表格 body 区域滚动，工具栏、搜索栏、表头不应随表格内容一起滚动。
5. 内容少时不应出现横向滚动条。
6. 出现纵向滚动条时，标题区、表头、表体列宽不得错位。
7. 滚动容器内的操作浮层不得被容器裁剪。

浮层执行要求：

1. Dropdown、Tooltip、Popover、Select 下拉面板等浮层组件，应挂载到 `document.body` 或统一的全局浮层容器。
2. 不要通过放开表格或页面外层 `overflow` 来解决浮层被裁剪的问题。
3. 表格仍应保持自己的滚动边界，浮层通过 portal 脱离滚动裁剪区域。
4. 浮层应设置高于页面内容区的层级，避免被 Header、Table、Drawer 等定位层遮挡。

## 4. 栅格与响应式

### 4.1 栅格体系

页面整体采用 `24 栅格体系`。

执行要求：

1. 页面横向布局按 24 栅格拆分。
2. 固定宽度区域保持固定。
3. 自适应区域按剩余空间伸缩。
4. Margin 和 Gutter 不随内容变化。

### 4.2 屏幕边距

| 屏幕宽度 | 页面左右边距 |
| --- | --- |
| 1024 | 16px |
| 1280 | 24px |
| 1366-1920 | 32px |
| 左侧导航典型场景 1280-1920 | 16px |

执行要求：

1. 有左侧菜单的后台页面，内容区左右边距优先使用 `16px`。
2. 普通页面根据屏幕宽度使用 `16px / 24px / 32px`。
3. 同一页面内边距应保持一致，不要局部随意变动。

### 4.3 栅格列间距

默认 Gutter 使用 `8px`。

执行要求：

1. 栅格列之间使用 8px 间距。
2. 页面响应时，Gutter 保持不变。
3. Column 宽度随容器自适应。

## 5. 间距规范

### 5.1 卡片间距

卡片之间的上下左右间距使用 `16px`。

执行要求：

1. 同一层级卡片之间保持 16px。
2. 不要出现 12px、14px、20px 等临时卡片间距。
3. 页面主内容区内多个卡片并列或上下排列时，统一使用 16px。

### 5.2 元素间距

| 参数 | 数值 | 使用场景 |
| --- | --- | --- |
| ElementMarginS | 4px | 图标与文字、紧凑控件内部元素 |
| ElementMarginM | 8px | 按钮组、筛选项、标签项之间 |
| ElementMarginL | 16px | 表单项组、搜索区、操作区、表格区之间 |

执行要求：

1. 图标和文本之间使用 4px。
2. 同一操作组内按钮之间使用 8px。
3. 搜索区、操作区、列表区之间使用 16px。
4. 表格上方工具栏与表格之间使用 16px 或按原图标注的 16px 体系执行。

## 6. 字体规范

### 6.1 字体族

| 类型 | 优先字体 | 备用字体 |
| --- | --- | --- |
| 中文 | 微软雅黑 | 苹方 |
| 英文 | Arial | San Francisco Display |

执行要求：

1. 中文优先使用微软雅黑。
2. 英文优先使用 Arial。
3. macOS 场景可使用苹方、San Francisco Display 作为备用字体。

### 6.2 字号与行高

行高规则：

```text
行高 = 字号 * 1.5
```

如计算结果为奇数或有余数，上调为临近偶数。

| 文本类型 | 字重 | 字号 | 行高 | 场景 |
| --- | --- | --- | --- | --- |
| Big Data | Regular | 48px | 72px | 仪表盘、图表等可视化强调的重要数据 |
| Headline1 标题1 | Regular | 20px | 30px | 首页、详情页等页面一级标题 |
| Headline2 标题2 | Bold | 18px | 28px | 页面内二级标题 |
| Headline3 标题3 | Regular | 16px | 24px | 页面内三级标题 |
| Body1 正文1 | Regular | 14px | 22px | 正文文本、组件填充文本 |
| Body2 正文2 | Bold | 14px | 22px | 折叠面板标题、四级标题 |
| Body3 正文3 | Regular | 12px | 18px | 辅助文本、图表坐标文本、列表表头、帮助文本、提示文本 |
| Badge 通知 | Bold | 10px | 16px | 徽标文本 |
| Button 1 按钮1 | Regular | 16px | 24px | 大按钮文本 |
| Button 2 按钮2 | Regular | 14px | 22px | 小按钮文本、文字按钮 |

### 6.3 字重

| 字重名称 | CSS 字重 |
| --- | --- |
| Regular | 400 |
| Bold | 700 |

执行要求：

1. 不要随意使用 500、600。
2. 强调信息使用 Bold 700。
3. 普通正文使用 Regular 400。

### 6.4 文本对齐

执行要求：

1. 大段文本默认左对齐。
2. 段落换行默认左对齐。
3. 标题、空页面描述、插画引导页可使用居中对齐。
4. 不要为了视觉居中牺牲大段文字阅读效率。

### 6.5 文案与控件本地化

执行要求：

1. 业务系统页面默认使用中文界面文案，所有用户可见的控件内置文案必须本地中文化。
2. 表单控件、日期/时间控件、分页器、上传控件、空状态、加载状态、确认弹窗、提示消息、校验错误、筛选项、操作按钮、下拉面板等，不得出现 `OK`、`Cancel`、`Now`、`Today`、`No Data`、`Upload` 等未本地化英文默认文案。
3. 使用 Ant Design、ProComponents 或其它第三方组件时，必须在应用入口或组件封装层统一配置中文 locale；单个控件如果仍有英文默认文案，必须通过组件属性显式覆盖为中文。
4. Placeholder、帮助文字、错误提示和按钮文案应使用符合业务语义的中文，不要直接使用组件库默认英文。
5. 业务编码、接口字段名、字典值、文件名、品牌名等确属业务数据时可以保留英文或英文数字混合，但不得把英文数据值误用为控件标签、按钮、提示或空状态文案。
6. AI 生成或修改页面时，必须检查截图、浏览器页面和组件快照中是否存在未本地化英文控件文案，发现后应立即修正。

## 7. 颜色规范

### 7.1 色彩原则

执行要求：

1. 系统主色使用橙色系。
2. 红色、黄色优先用于告警、危险、警示场景。
3. 品牌橙色与告警色冲突时，应使用冷色与中性色辅助。
4. 颜色用于表达状态、反馈、数据可视化时，应谨慎使用。
5. 正常模式下前景色与背景色对比值至少达到 `3:1`。
6. 普通文本建议达到 `4.5:1`。
7. 大号文本建议达到 `3:1`。

## 8. 圆角、描边、阴影

### 8.1 圆角

| 类型 | 数值 | 场景 |
| --- | --- | --- |
| 圆角半径 XS | 1px | 16px 图标 |
| 圆角半径 S | 2px | 24px 图标、多选框 |
| 圆角半径 M | 4px | 32px 图标、输入框、按钮 |
| 圆角半径 L | 8px | 弹框 |

执行要求：

1. 图标圆角跟随图标大小变化。
2. 多选框圆角使用 2px。
3. 输入框、按钮圆角使用 4px。
4. 弹框圆角使用 8px。

### 8.2 描边

默认使用 `1px` 描边。

适用组件：

1. 多选框。
2. 单选框。
3. 输入框。
4. 下拉选择。
5. 按钮。
6. 卡片。
7. 进度条。
8. 横向柱状图。

## 9. 顶部栏与全局导航

### 9.1 顶部栏结构

顶部栏必须包含：

1. 主菜单入口。
2. 产品名称或产品页签。
3. 全局功能区。
4. 账号信息。

### 9.2 产品名称

执行要求：

1. 没有产品特有 Logo 时，使用公司 Logo + 产品名称。
2. 当系统有首页或总览页时，点击产品名称返回首页。
3. 产品名称点击热区高度为 32px。
4. 产品名称点击热区宽度根据产品名称自适应。

### 9.3 全局功能区

全局功能区可放置：

1. 用户需要随时关注的内容，如记录、消息等。
2. 用户经常使用的功能，如帮助等。

执行要求：

1. 全局功能区应在站点任何位置可用。
2. 全局功能区不应放置强业务流程中的普通操作。
3. 用户打开多个场景时，除工作台外最多显示 3 个场景。
4. 超过 3 个场景时，使用尾部省略和溢出承载。

## 10. 左侧导航

### 10.1 菜单层级

左侧导航采用两级结构：

1. 收起按钮。
2. 一级菜单。
3. 二级菜单。

执行要求：

1. 一级菜单可作为页面入口。
2. 一级菜单也可只作为分类展开入口。
3. 用户可能跨模块完成任务，一次可展开多个菜单。
4. 不强制一次只能展开一个菜单。

### 10.2 菜单文字

建议中文字符不超过 8 个。

执行要求：

1. 左侧菜单文字必须准确。
2. 左侧菜单文字必须精炼。
3. 不要把解释性描述放进菜单名。

### 10.3 菜单状态样式

| 状态 | 视觉要求 |
| --- | --- |
| Active | 图标 24x24，#D9D9D9；文字 18px，#4D4D4D；背景 #FFFFFF |
| Hover | 图标 24x24，#D9D9D9；文字 18px，#E75927；背景 #FFEFEA |
| 默认 | 图标 24x24，#4D4D4D；文字 16px，#4D4D4D；背景 #F5F5F5 |

## 11. 页签

页签用于多个相关内容之间快速切换。

执行要求：

1. 页签必须区分已选中与未选中状态。
2. 建议页签数量控制在 5 个以内。
3. 页签数量过多时，应改用更合适的信息组织方式。
4. 页签不应承载无关内容。

## 12. 步骤

步骤用于引导用户完成某项任务。

步骤结构包括：

1. 状态图标。
2. 连接线。
3. 步骤标签。

执行要求：

1. 步骤节点尺寸使用 20x20px。
2. 步骤文本使用 14px。
3. 当前或主色状态使用 #E75927。
4. 横向空间有限时，文字可放在步骤点下方。

## 13. 面包屑

面包屑用于展示当前页面所处层级结构。

结构包括：

1. 页面链接。
2. 分隔符。
3. 当前页。

视觉要求：

| 元素 | 样式 |
| --- | --- |
| 链接 | 14px，#2673E5 |
| 普通层级文本 | 14px，#808080 |
| 当前页标题 | 26px，Bold，#808080 |

执行要求：

1. 层级过长时中间层级可省略。
2. 当前页可根据场景选择是否展示。
3. 面包屑与内容标题之间应保持清晰层级。

标签是独立的简单对象容器。

结构包括：

1. 标签容器。

## 15. 搜索栏

搜索栏用于可搜索输入。

结构包括：

1. 搜索框。
2. 搜索图标。
3. 占位文字，可选。
4. 清空按钮，可选。

执行要求：

1. 搜索图标统一放在输入框前部。
2. 开始输入内容时，占位文字消失。
3. 开始输入内容时，出现清空按钮。
4. 回车触发型搜索必须支持 Enter 键触发。

基础样式：

| 状态 | 样式 |
| --- | --- |
| Normal | 高度 26px；圆角 4px；背景 #F0F2F4；占位文字 14px，#B2B2B2 |

## 16. 表单

### 16.1 表单设计原则

表单必须符合：

1. 保证安全性。
2. 提高可理解性。
3. 提高填写效率。

执行要求：

1. 对高风险配置应提供校验和确认机制。
2. 对陌生概念应提供帮助文字或说明。
3. 高频录入场景应减少非必要字段干扰。

### 16.2 表单结构

基础表单包含：

1. 标签。
2. 输入域。
3. 提交操作按钮，可选。

对于及时生效的表单，可以不需要操作按钮。

### 16.3 表单容器选择

| 容器 | 使用条件 | 布局 |
| --- | --- | --- |
| 气泡窗 | 表单内容小于等于 3 条，且内容不重要或较轻量 | 只能单列 |
| 抽屉 | 表单内容大于等于 4 条，一般表单默认选择 | 建议单列，可按场景双列 |
| 全页面 | 极复杂表单、复杂子项添加、初始化配置 | 单列或双列 |

执行要求：

1. 抽屉是系统默认表单容器。
2. 抽屉标题区固定。
3. 抽屉操作区固定。
4. 全页面表单操作区固定。
5. 全页面标题区域的步骤控件滚动固定。
6. 全页面表单标题一般不固定。

### 16.4 表单标题层级

表单最多支持三级标题，但建议最多使用两级。

执行要求：

1. 一级标题用于表单标题。
2. 二级标题用于群组标签。
3. 三级标题用于子群组标签。
4. 不要在普通业务表单中堆叠过多标题层级。

### 16.5 占位文字

占位文字不能包含关键信息。

占位文字可用于：

1. 提供填写样例或格式，如姓名样例、电话格式、日期格式。
2. 提示用户需要输入的内容。

执行要求：

1. 占位文字不能看起来像真实输入内容。
2. 关键规则应使用标签或帮助文字，不要只放在 placeholder。
3. 用户输入后 placeholder 消失，不应导致信息丢失。

### 16.6 帮助文字与错误提示

帮助文字用于辅助用户完成输入，包括数量限制、内容规范等。

执行要求：

1. 帮助文字应放在输入项附近。
2. 错误提示是特殊帮助文字。
3. 校验错误后，错误提示应说明错误原因，并尽量给出解决方案。
4. 同一位置同时存在帮助文字和错误提示时，错误提示优先。
5. 用户清除或重新输入目标输入框内容时，错误提示消失，原帮助文字恢复。
6. 即时校验的输入框不需要额外错误提示文字，只需把未满足条件的项标红。

### 16.7 必填与选填

执行要求：

1. 必填、选填标记逻辑必须统一。
2. 如果没有标签，可借助占位文字、表头等表示必填和非必填。
3. 同一表单内不要一部分标必填、一部分标选填，除非整体规则明确。

### 16.8 提交校验

执行要求：

1. 提交按钮默认始终可点击。
2. 提交后统一校验全部内容。
3. 组合信息校验应在提交时执行，如用户名和密码是否匹配。
4. 表单过长时，应提供能快速定位错误项的能力。

### 16.9 表格添加

建议适用场景：

1. 输入内容属性一致。
2. 输入数量满足 `2 <= 数量 <= 5`。
3. 输入内容需要表头来标明。

执行要求：

1. 表格添加可采用统一保存校验。
2. 表格添加也可采用单行保存校验。
3. 如果采用单行校验，每次添加必须保存后才可添加下一条。
4. 单行校验时，每次只能修改一条。
5. 编辑态可用于规避误操作。
6. 逐行添加可提高输入准确性。

### 16.10 高级设置

执行要求：

1. 简单表单如有高级设置，默认放在表单底部。
2. 高级设置默认通过折叠面板展开和收起。
3. 高级设置中不应该存在必填项。
4. 高级设置标题应尽量与内容对应。
5. 标题不必须叫 `Advanced Setting` 或 `高级设置`。
6. 如果高级设置与某个分组强相关，可使用分组高级设置。

## 17. 表格

### 17.1 表格结构

表格包含：

1. 页签，可选。
2. 操作栏，可选。
3. 表头。
4. 表格行。
5. 分页，可选。

操作区域可包含：

1. 对象普通操作按钮及批量操作按钮区，如增加、删除、编辑等。
2. 表格筛选区。
3. 页签操作区。

### 17.2 表格文字样式

| 编号 | 样式 |
| --- | --- |
| 1 | 16px，#E75927 |
| 2 | 16px，#808080 |
| 3 | 14px，#1A1A1A |
| 4 | 12px，#808080 |

### 17.3 表格响应规则

执行要求：

1. 除固定宽度列外，表格列整体均匀响应。
2. 响应时，每一列均分减少的宽度。
3. 某一列响应到最小宽度后，不再继续变小。
4. 固定宽度列不参与响应。
5. 页面横向宽度无法承载时，才出现表格内横向滚动条。
6. 页面本身不应出现无意义横向滚动条。

### 17.4 表头最小宽度

建议设置默认表头最小宽度：

```text
完整表头文字宽度 + 表头操作宽度
```

执行要求：

1. 表头文字应尽量完整展示。
2. 表头文字完整性优先于列过度压缩。
3. 表头有筛选、排序等操作时，最小宽度必须包含操作控件宽度。

### 17.5 表格列宽设置

执行要求：

1. 表格列宽可基于 1920 分辨率设计。
2. 固定宽度列之外，剩余列可根据内容长度设置初始值。
3. 未设置初始值的列默认平分剩余宽度。
4. 内容长度相对固定的列，在列表内容较多时可设置固定宽度。
5. 重要列可设置固定宽度或最小宽度。
6. 如要求各分辨率下默认完整展示，必须覆盖多分辨率测试。

### 17.6 表格滚动

执行要求：

1. 表格数据超过可视高度时，表格 body 区域纵向滚动。
2. 表格搜索区、操作区、页签区不随表格 body 滚动。
3. 表头应与表格 body 列宽对齐。
4. 出现纵向滚动条时，不得导致表头和表体错位。
5. 内容未超过容器宽度时，不得出现横向滚动条。

## 18. 页面验收清单

开发完成后必须逐项检查：

### 18.1 布局检查

1. 页面是否采用 Header + Sidebar + Content 结构。
2. 左侧菜单展开宽度是否为 200px。
3. 左侧菜单收起宽度是否为 100px。
4. 顶部栏高度是否为 40px。
5. 内容区是否自适应。
6. 页面是否没有无意义横向滚动条。
7. 内容超过高度时，滚动条是否出现在正确区域。

### 18.2 间距检查

1. 页面左右边距是否符合屏幕宽度规则。
2. 有左侧导航场景内容边距是否优先使用 16px。
3. 卡片间距是否为 16px。
4. 图标与文字间距是否为 4px。
5. 按钮组间距是否为 8px。
6. 搜索区、操作区、列表区之间是否为 16px。

### 18.3 字体检查

1. 中文字体是否优先使用微软雅黑。
2. 英文字体是否优先使用 Arial。
3. 字号是否来自规范表。
4. 行高是否按字号 1.5 倍计算并上调到临近偶数。
5. 字重是否只使用 400 和 700。

### 18.4 本地化检查

1. 控件内置文案是否已统一中文化。
2. 日期/时间控件、分页器、上传控件、空状态、加载状态、确认弹窗是否没有英文默认文案。
3. Placeholder、帮助文字、错误提示、按钮文案是否为业务语义明确的中文。
4. 第三方组件是否已配置中文 locale，不能依赖英文默认值。
5. 页面截图或浏览器检查中是否没有 `OK`、`Cancel`、`Now`、`Today`、`No Data`、`Upload` 等英文默认控件文案。
6. 保留英文的内容是否确认为业务数据、业务编码、字段名、文件名或品牌名，而不是控件 UI 文案。

### 18.5 颜色检查

1. 主色是否使用 #E75927。
2. Hover 主色是否使用 #FF7A42。
3. Active 主色是否使用 #D42F00。
4. 正文主要文本是否使用 #1A1A1A。
5. 次要文本是否使用 #4D4D4D。
6. 提示文本是否使用 #808080 或 #B3B3B3。
7. 链接是否使用 #2673E5。
8. 告警、危险、警示是否未滥用品牌橙色。

### 18.6 组件检查

1. 输入框、按钮圆角是否为 4px。
2. 弹框圆角是否为 8px。
3. 常规描边是否为 1px。
4. 下拉框、气泡窗、抽屉、对话框阴影是否符合规范。
5. 标签 Normal、Hover、Active、Disable 状态是否齐全。
6. 搜索框是否支持输入后显示清空按钮。
7. 回车触发型搜索是否支持 Enter 键。

### 18.7 表单检查

1. 表单容器是否按字段数量和复杂度选择。
2. 小于等于 3 条轻量表单是否优先气泡窗。
3. 大于等于 4 条普通表单是否优先抽屉。
4. 复杂表单是否使用全页面。
5. 抽屉标题区和操作区是否固定。
6. 全页面操作区是否固定。
7. 表单标题层级是否不超过两级为主。
8. Placeholder 是否没有承载关键信息。
9. 帮助文字和错误提示是否位置一致。
10. 提交按钮是否默认可点击。

### 18.8 表格检查

1. 表格是否包含必要的页签、操作栏、表头、行、分页。
2. 表头最小宽度是否覆盖完整表头文字和操作控件。
3. 固定宽度列是否不参与响应。
4. 自适应列是否均匀响应。
5. 横向空间不足时，是否只在表格内部出现横向滚动。
6. 内容未超宽时，是否没有横向滚动条。
7. 数据超高时，是否只让表格 body 纵向滚动。
8. 表头和表体是否对齐。

## 19. AI 生成页面时的执行提示

AI 生成或修改页面时，必须按以下顺序处理：

1. 先确定页面结构：Header、Sidebar、Content、是否需要表格或表单。
2. 再确定容器：普通页面、抽屉、气泡窗、全页面。
3. 再套用间距：4px、8px、16px、屏幕边距。
4. 再套用字体：字号、行高、字重。
5. 再套用颜色：主色、文本色、状态色、告警色。
6. 再处理滚动：页面、侧栏、内容区、表格 body。
7. 再处理本地化：控件内置文案、提示、校验、空状态、确认弹窗必须中文化。
8. 最后做验收：横向滚动、纵向滚动、表头对齐、按钮间距、表单校验、本地化、响应式。

AI 不应：

1. 随意新增规范中没有的颜色。
2. 随意新增 12px、20px 等非规范间距作为主间距。
3. 使用页面整体滚动替代表格 body 滚动。
4. 在普通后台业务页面中使用过度装饰。
5. 把 placeholder 当作关键说明。
6. 把高级设置设计成必填区域。
7. 让内容少的表格出现横向滚动条。
8. 让纵向滚动条导致表头和表体错位。
9. 让第三方控件显示未本地化英文默认文案。
