# 企业端前端部署说明

本文档说明企业端前端在测试环境的 Jenkins 构建、打包和静态部署方式。企业端采用主应用加 qiankun 子应用结构，主应用负责整体布局、路由入口和微应用加载，七个子应用按独立仓库构建后发布到主应用站点下的 `microapps` 目录。

> 注意：平台端和企业端是两套前端部署对象。平台端使用 `sc-cloud-basic`、`sc-cloud-platform`；企业端使用 `sc-cloud-basic-platform`、`sc-cloud-design-form`、`sc-cloud-fm-budget`、`sc-cloud-fm-treasury`、`sc-cloud-fm-accounting`、`sc-cloud-mdm`、`sc-cloud-procurement`、`sc-cloud-expense`。两端可以复用 Jenkins 写法和服务器工具链，但不要共用同一个构建包，也不要把两个端的产物混到同一个发布目录里。

## 0. 平台端与企业端对照

| 部署对象 | 仓库组合 | Jenkins 包名建议 | 发布根目录 | 访问域名 |
| --- | --- | --- | --- | --- |
| 平台端 | `sc-cloud-core` + `sc-cloud-basic` + `sc-cloud-platform` | `sc-cloud-test-v3-${RELEASE_ID}.tar.gz` | `/home/sc_cloud_v3/pc-web` | `https://test-v3.szyplus.com/` |
| 企业端 | `sc-cloud-core` + `sc-cloud-basic-platform` + 企业端子应用 | `sc-cloud-enterprise-test-${RELEASE_ID}.tar.gz` | `/home/sc_cloud_v3/enterprise-web` | `https://enterprise-test-v3.szyplus.com/` |

企业端后续使用独立域名和独立目录。平台端脚本只作为写法参考，不作为企业端默认部署目标。平台端和企业端建议拆成两个 Jenkins Job；企业端内部可以用一个 Jenkins Job 统一编排多个业务系统，通过复选框选择本次要构建和发布的系统。

企业端业务系统仍保持“一个业务系统一个独立仓库、独立版本、独立构建产物”的边界。Jenkins 合并的是部署入口和流水线模板，不合并代码仓库、不合并版本号、不强制所有系统同版本发布。例如 A 系统可以发布 `1.0.0`，B 系统可以发布 `1.0.2`。

## 0.1 企业端单 Job 多系统发布模型

运维希望的“合并一下”，建议理解为：企业端只保留一个 Jenkins 发布入口，在这个 Job 上用 `BUILD_SERVICES` 复选框选择本次发布哪些业务系统。勾选哪个系统，就检出、构建、打包、同步哪个系统的产物；未勾选的系统不进入本次发布包，服务器上已有目录也不做清理。

这个模型解决的是发布入口统一和运维操作简化，不改变研发侧的仓库和版本边界：

| 维度 | 约定 |
| --- | --- |
| 代码仓库 | 一个业务系统一个独立仓库 |
| 版本号 | 每个业务系统独立控制版本 |
| 构建产物 | 每个业务系统独立产出 `dist` |
| Jenkins Job | 企业端可以共用一个发布 Job |
| 发布选择 | 通过 `BUILD_SERVICES` 勾选本次要发布的系统 |
| 增量发布 | 只覆盖本次勾选系统对应的发布目录 |

因此可以出现这种发布状态：基础平台当前是 `1.0.0`，表单设计当前是 `1.0.2`，预算管理当前是 `1.0.1`，财资系统当前是 `1.0.0`。后续如果只修了表单设计，就只勾选 `sc-cloud-design-form` 发布，基础平台和其他子应用目录保持原版本不变。

## 2. 企业端部署目录

企业端测试环境使用独立部署目录和独立域名。服务器可复用同一台机器，但站点根目录必须与平台端分开：

```text
DEPLOY_HOST=root@192.168.2.9
DEPLOY_ROOT=/home/sc_cloud_v3/enterprise-web
TEST_URL=https://enterprise-test-v3.szyplus.com/
```

企业端静态目录约定如下：

| 应用 | 发布目录 | 访问入口 |
| --- | --- | --- |
| `sc-cloud-basic-platform` | `${DEPLOY_ROOT}` | `/`、`/basic` |
| `sc-cloud-design-form` | `${DEPLOY_ROOT}/microapps/design-form` | `/design_form` |
| `sc-cloud-fm-budget` | `${DEPLOY_ROOT}/microapps/fm-budget` | `/fm_budget` |
| `sc-cloud-fm-treasury` | `${DEPLOY_ROOT}/microapps/fm-treasury` | `/fm_treasury` |
| `sc-cloud-fm-accounting` | `${DEPLOY_ROOT}/microapps/fm-accounting` | `/fm_accounting` |
| `sc-cloud-mdm` | `${DEPLOY_ROOT}/microapps/mdm` | `/mdm` |
| `sc-cloud-procurement` | `${DEPLOY_ROOT}/microapps/procurement` | `/procurement` |
| `sc-cloud-expense` | `${DEPLOY_ROOT}/microapps/expense` | `/expense` |

如果实际企业端域名不是 `enterprise-test-v3.szyplus.com`，只替换 `TEST_URL`、Nginx `server_name` 和 DNS 解析即可；不要把企业端 `DEPLOY_ROOT` 指回平台端的 `/home/sc_cloud_v3/pc-web`。

主应用构建环境必须配置所有子应用入口：

```env
VITE_DESIGN_FORM_ENTRY=/microapps/design-form/
VITE_FM_BUDGET_ENTRY=/microapps/fm-budget/
VITE_FM_TREASURY_ENTRY=/microapps/fm-treasury/
VITE_FM_ACCOUNTING_ENTRY=/microapps/fm-accounting/
VITE_MDM_ENTRY=/microapps/mdm/
VITE_PROCUREMENT_ENTRY=/microapps/procurement/
VITE_EXPENSE_ENTRY=/microapps/expense/
```

这些变量会被主应用 qiankun 注册逻辑读取。缺失或路径错误时，主应用可以正常打开，但点击对应业务系统会加载不到子应用。

## 3. Jenkins Pipeline 参考

以下 Pipeline 基于平台端脚本调整而来，但构建对象、仓库、包名和发布目录都按企业端处理。这个 Jenkins Job 用 `BUILD_SERVICES` 复选框实现“勾选哪个系统就构建和发布哪个系统”。首次部署建议全选主应用和七个子应用；后续可按变更范围选择增量构建，但如果主应用环境变量、公共依赖或共享包发生变化，应全量构建。

截图里的平台端 Job 只有一个 `git_branch`，这表示所有勾选应用都使用同一个分支。企业端如果要支持各业务系统独立发版，需要把参数改成“一个仓库一个分支参数”：`CORE_BRANCH`、`BASIC_PLATFORM_BRANCH`、`DESIGN_FORM_BRANCH`、`FM_BUDGET_BRANCH`、`FM_TREASURY_BRANCH`、`FM_ACCOUNTING_BRANCH`、`MDM_BRANCH`、`PROCUREMENT_BRANCH`、`EXPENSE_BRANCH`。`BUILD_SERVICES` 仍然只负责选择本次发布哪些应用；未勾选应用对应的分支参数可以不改，也可以留空。

下面示例用 `string` 参数填写分支名，兼容性最好。如果运维希望继续使用截图里的下拉选择，可以把这些 `string` 参数改成 Git Parameter 插件参数，并为每个参数配置对应仓库的 `useRepository`，例如 `.*sc-cloud-design-form.git`。关键点是不要再只保留一个全局 `git_branch`。

```groovy
pipeline {
    agent any

    options {
        disableConcurrentBuilds()
        buildDiscarder(logRotator(numToKeepStr: '30'))
        timeout(time: 30, unit: 'MINUTES')
    }

    parameters {
        string(
            name: 'CORE_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-core 分支'
        )
        string(
            name: 'BASIC_PLATFORM_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-basic-platform 分支；勾选基础平台时生效'
        )
        string(
            name: 'DESIGN_FORM_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-design-form 分支；勾选表单设计时生效'
        )
        string(
            name: 'FM_BUDGET_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-fm-budget 分支；勾选预算管理时生效'
        )
        string(
            name: 'FM_TREASURY_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-fm-treasury 分支；勾选财资系统时生效'
        )
        string(
            name: 'FM_ACCOUNTING_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-fm-accounting 分支；勾选财会系统时生效'
        )
        string(
            name: 'MDM_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-mdm 分支；勾选主数据系统时生效'
        )
        string(
            name: 'PROCUREMENT_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-procurement 分支；勾选招采系统时生效'
        )
        string(
            name: 'EXPENSE_BRANCH',
            defaultValue: 'dev',
            description: 'sc-cloud-expense 分支；勾选费用报销系统时生效'
        )
        extendedChoice(
            name: 'BUILD_SERVICES',
            type: 'PT_CHECKBOX',
            value: 'sc-cloud-basic-platform,sc-cloud-design-form,sc-cloud-fm-budget,sc-cloud-fm-treasury,sc-cloud-fm-accounting,sc-cloud-mdm,sc-cloud-procurement,sc-cloud-expense',
            defaultValue: 'sc-cloud-basic-platform,sc-cloud-design-form,sc-cloud-fm-budget,sc-cloud-fm-treasury,sc-cloud-fm-accounting,sc-cloud-mdm,sc-cloud-procurement,sc-cloud-expense',
            multiSelectDelimiter: ',',
            quoteValue: false,
            visibleItemCount: 8,
            description: '选择本次需要构建和部署的企业端前端应用；首次部署必须全选'
        )
    }

    environment {
        NODE_HOME = '/mnt/nodejs'
        PATH = "${NODE_HOME}/bin:${env.PATH}"

        CORE_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-core.git'
        BASIC_PLATFORM_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-basic-platform.git'
        DESIGN_FORM_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-design-form.git'
        FM_BUDGET_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-fm-budget.git'
        FM_TREASURY_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-fm-treasury.git'
        FM_ACCOUNTING_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-fm-accounting.git'
        MDM_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-mdm.git'
        PROCUREMENT_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-procurement.git'
        EXPENSE_REPO = 'http://office.szyplus.com:3101/sc-cloud/sc-cloud-expense.git'

        GIT_CREDENTIALS_ID = '5027bb15-3a62-475b-a229-7fc44e5021a3'
        DEPLOY_HOST = 'root@192.168.2.9'
        DEPLOY_ROOT = '/home/sc_cloud_v3/enterprise-web'
        DEPLOY_SCRIPT = '/home/sc_cloud_v3/deploy-enterprise-web-test.sh'
        TEST_URL = 'https://enterprise-test-v3.szyplus.com/'
        RELEASE_ID = "${BUILD_NUMBER}-${BUILD_TAG}"
    }

    stages {
        stage('Resolve Selection') {
            steps {
                script {
                    def allowed = [
                        'sc-cloud-basic-platform',
                        'sc-cloud-design-form',
                        'sc-cloud-fm-budget',
                        'sc-cloud-fm-treasury',
                        'sc-cloud-fm-accounting',
                        'sc-cloud-mdm',
                        'sc-cloud-procurement',
                        'sc-cloud-expense'
                    ]
                    def selected = (params.BUILD_SERVICES ?: '')
                        .split(',')
                        .collect { it.trim() }
                        .findAll { it }
                        .unique()
                    def normalizeBranch = { value ->
                        return (value ?: '').trim().replaceFirst(/^origin\\//, '')
                    }
                    def validateBranch = { name, value ->
                        if (!value || value ==~ /.*\\.\\..*/ || !(value ==~ /[A-Za-z0-9._\\/-]+/)) {
                            error("非法 ${name}：${value}")
                        }
                    }

                    if (selected.isEmpty()) {
                        error('BUILD_SERVICES 不能为空')
                    }

                    def invalid = selected.findAll { !allowed.contains(it) }
                    if (!invalid.isEmpty()) {
                        error("存在非法服务选择：${invalid.join(',')}")
                    }

                    env.CORE_BRANCH_NAME = normalizeBranch(params.CORE_BRANCH)
                    env.BASIC_PLATFORM_BRANCH_NAME = normalizeBranch(params.BASIC_PLATFORM_BRANCH)
                    env.DESIGN_FORM_BRANCH_NAME = normalizeBranch(params.DESIGN_FORM_BRANCH)
                    env.FM_BUDGET_BRANCH_NAME = normalizeBranch(params.FM_BUDGET_BRANCH)
                    env.FM_TREASURY_BRANCH_NAME = normalizeBranch(params.FM_TREASURY_BRANCH)
                    env.FM_ACCOUNTING_BRANCH_NAME = normalizeBranch(params.FM_ACCOUNTING_BRANCH)
                    env.MDM_BRANCH_NAME = normalizeBranch(params.MDM_BRANCH)
                    env.PROCUREMENT_BRANCH_NAME = normalizeBranch(params.PROCUREMENT_BRANCH)
                    env.EXPENSE_BRANCH_NAME = normalizeBranch(params.EXPENSE_BRANCH)
                    env.SELECTED_SERVICES = selected.join(',')
                    env.BUILD_BASIC_PLATFORM = selected.contains('sc-cloud-basic-platform').toString()
                    env.BUILD_DESIGN_FORM = selected.contains('sc-cloud-design-form').toString()
                    env.BUILD_FM_BUDGET = selected.contains('sc-cloud-fm-budget').toString()
                    env.BUILD_FM_TREASURY = selected.contains('sc-cloud-fm-treasury').toString()
                    env.BUILD_FM_ACCOUNTING = selected.contains('sc-cloud-fm-accounting').toString()
                    env.BUILD_MDM = selected.contains('sc-cloud-mdm').toString()
                    env.BUILD_PROCUREMENT = selected.contains('sc-cloud-procurement').toString()
                    env.BUILD_EXPENSE = selected.contains('sc-cloud-expense').toString()

                    validateBranch('CORE_BRANCH', env.CORE_BRANCH_NAME)
                    if (env.BUILD_BASIC_PLATFORM == 'true') {
                        validateBranch('BASIC_PLATFORM_BRANCH', env.BASIC_PLATFORM_BRANCH_NAME)
                    }
                    if (env.BUILD_DESIGN_FORM == 'true') {
                        validateBranch('DESIGN_FORM_BRANCH', env.DESIGN_FORM_BRANCH_NAME)
                    }
                    if (env.BUILD_FM_BUDGET == 'true') {
                        validateBranch('FM_BUDGET_BRANCH', env.FM_BUDGET_BRANCH_NAME)
                    }
                    if (env.BUILD_FM_TREASURY == 'true') {
                        validateBranch('FM_TREASURY_BRANCH', env.FM_TREASURY_BRANCH_NAME)
                    }
                    if (env.BUILD_FM_ACCOUNTING == 'true') {
                        validateBranch('FM_ACCOUNTING_BRANCH', env.FM_ACCOUNTING_BRANCH_NAME)
                    }
                    if (env.BUILD_MDM == 'true') {
                        validateBranch('MDM_BRANCH', env.MDM_BRANCH_NAME)
                    }
                    if (env.BUILD_PROCUREMENT == 'true') {
                        validateBranch('PROCUREMENT_BRANCH', env.PROCUREMENT_BRANCH_NAME)
                    }
                    if (env.BUILD_EXPENSE == 'true') {
                        validateBranch('EXPENSE_BRANCH', env.EXPENSE_BRANCH_NAME)
                    }

                    currentBuild.description = "core=${env.CORE_BRANCH_NAME}, services=${env.SELECTED_SERVICES}"
                }
            }
        }

        stage('Checkout') {
            steps {
                deleteDir()

                dir('sc-cloud-core') {
                    checkout scmGit(
                        branches: [[name: "refs/heads/${env.CORE_BRANCH_NAME}"]],
                        userRemoteConfigs: [[
                            credentialsId: env.GIT_CREDENTIALS_ID,

                }

                if (env.BUILD_BASIC_PLATFORM == 'true') {
                    dir('sc-cloud-core/apps/sc-cloud-basic-platform') {
                        checkout scmGit(
                            branches: [[name: "refs/heads/${env.BASIC_PLATFORM_BRANCH_NAME}"]],

                if (env.BUILD_DESIGN_FORM == 'true') {

                            branches: [[name: "refs/heads/${env.DESIGN_FORM_BRANCH_NAME}"]],
```

## 4. 部署脚本约定

`DEPLOY_SCRIPT` 可参考平台端脚本实现，关键是按企业端包结构同步目录：

```bash
#!/usr/bin/env bash
set -euo pipefail

RELEASE_ID="$1"
PACKAGE="$2"
TEST_URL="$3"

DEPLOY_ROOT="/home/sc_cloud_v3/enterprise-web"
RELEASE_DIR="/home/sc_cloud_v3/releases/enterprise-web-${RELEASE_ID}"

mkdir -p "${RELEASE_DIR}"
tar -xzf "${PACKAGE}" -C "${RELEASE_DIR}"

if [ -d "${RELEASE_DIR}/basic-platform" ]; then
  rsync -a --delete "${RELEASE_DIR}/basic-platform/" "${DEPLOY_ROOT}/"
fi

if [ -d "${RELEASE_DIR}/microapps/design-form" ]; then

  rsync -a --delete "${RELEASE_DIR}/microapps/design-form/" "${DEPLOY_ROOT}/microapps/design-form/"

if [ -d "${RELEASE_DIR}/microapps/fm-budget" ]; then
  mkdir -p "${DEPLOY_ROOT}/microapps/fm-budget"
  rsync -a --delete "${RELEASE_DIR}/microapps/fm-budget/" "${DEPLOY_ROOT}/microapps/fm-budget/"

if [ -d "${RELEASE_DIR}/microapps/fm-treasury" ]; then

if [ -d "${RELEASE_DIR}/microapps/fm-accounting" ]; then
```

## 6. 发布后验证

发布完成后按下面顺序验证：

1. 访问 `https://enterprise-test-v3.szyplus.com/`，确认主应用首页可打开。
2. 直接刷新 `/basic` 或任一基础平台深层路由，确认不 404。
3. 点击顶部应用切换进入“表单设计”，确认 URL 进入 `/design_form`，页面正常渲染。
4. 点击顶部应用切换进入“预算管理”，确认 URL 进入 `/fm_budget`，页面正常渲染。
5. 点击顶部应用切换进入“财资系统”“财会系统”“主数据系统”“招采系统”“费用报销系统”，确认 URL 分别进入 `/fm_treasury`、`/fm_accounting`、`/mdm`、`/procurement`、`/expense`，页面正常渲染。
6. 浏览器 Network 中确认：
   - 表单设计入口从 `/microapps/design-form/` 加载。
   - 预算管理入口从 `/microapps/fm-budget/` 加载。
   - 财资系统入口从 `/microapps/fm-treasury/` 加载。
   - 财会系统入口从 `/microapps/fm-accounting/` 加载。
   - 主数据系统入口从 `/microapps/mdm/` 加载。
   - 招采系统入口从 `/microapps/procurement/` 加载。
   - 费用报销系统入口从 `/microapps/expense/` 加载。
   - API 请求仍走 `/api` 或后端代理，不出现 `localhost`。
7. 直接刷新任一子应用激活路由，例如 `/design_form/...`、`/fm_budget/...`、`/fm_treasury/...`、`/fm_accounting/...`、`/mdm/...`、`/procurement/...`、`/expense/...`，确认仍返回主应用并能加载对应子应用。

## 7. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 主应用正常，子应用空白 | 检查 `VITE_DESIGN_FORM_ENTRY`、`VITE_FM_BUDGET_ENTRY`、`VITE_FM_TREASURY_ENTRY`、`VITE_FM_ACCOUNTING_ENTRY`、`VITE_MDM_ENTRY`、`VITE_PROCUREMENT_ENTRY`、`VITE_EXPENSE_ENTRY` 是否存在且指向 `/microapps/*/` |
| 子应用激活路由刷新 404 | 检查 Nginx 是否将 `/design_form`、`/fm_budget`、`/fm_treasury`、`/fm_accounting`、`/mdm`、`/procurement`、`/expense` 回退到主应用 `index.html` |
| 子应用静态资源 404 | 检查 `release/microapps/*` 是否同步到 `${DEPLOY_ROOT}/microapps/*` |
| 子应用菜单不显示 | 检查子应用是否通过 qiankun `basicActions.setGlobalState` 上报 `appKey` 和 `menu` |
| API 请求打到 localhost | 检查子应用 `.env.test` 和 Nginx `/api` 代理配置 |
| 增量发布后菜单或公共组件异常 | 优先全量构建并发布主应用和所有企业端子应用，确认共享包和主应用菜单配置一致 |
